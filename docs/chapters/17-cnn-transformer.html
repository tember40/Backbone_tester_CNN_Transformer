제17장 · 이름보다 연산을 비교하다CNN과 Transformer

모델을 연대순으로 읽는 것과 같은 기준으로 비교하는 것은 다릅니다. 이제 어느 위치의 정보를, 어떤 가중치로, 어떤 비용을 들여 모으는가라는 질문으로 두 계열을 다시 보겠습니다. 이 장은 우승 모델을 고르는 순위표가 아니라 다음 실험의 비교 기준을 만드는 과정입니다.

학습 목표

  • 학습 가능한 고정 커널과 입력에 따라 계산되는 Attention 가중치를 구분합니다.
  • 한 층의 연결 범위와 여러 층의 누적 수용영역을 구분합니다.
  • 특징맵·토큰·피라미드를 같은 shape 기준으로 읽습니다.
  • 파라미터·연산량·메모리·지연시간을 분리하여 비교합니다.
17.1

여러 논문을 잇는 질문

17.1 “어느 쪽이 더 좋은가?” 전에

ViT는 대규모 사전학습과 전이의 조건에서 Transformer를 이미지 분류에 적용했습니다. ConvNeXt는 CNN의 학습 절차와 구조를 현대화하여 비교했습니다. 서로 다른 데이터·해상도·학습 방법으로 얻은 숫자를 모델 이름만 보고 정렬하면 구조의 효과와 실험 조건의 효과가 섞입니다.

참고할 출발점은 ViT §3.1의 구조적 가정과 ConvNeXt의 설계 비교입니다. 여기서는 논문 성능을 새로 측정하지 않습니다. 먼저 구조적으로 확실한 성질을 구분하고, 어느 조건에서 유리한지는 실험으로 확인할 질문으로 남깁니다.

17.2

같은 입력, 다른 결합

17.2 무엇이 고정되고 무엇이 달라질까?

기본적인 합성곱과 전역 Self-Attention · 모든 변형을 대표하는 규칙은 아님
질문일반 합성곱Self-Attention
공간 연결커널이 정한 이웃을 읽음mask가 없다면 모든 Key 위치와 비교
결합 계수학습한 커널을 각 입력에 적용학습한 Q/K 투영으로 현재 입력의 계수를 계산
값의 전달입력 채널과 공간 성분을 곱해 합산Attention 계수로 V를 가중합한 뒤 출력 투영
한 층의 범위커널·dilation 등으로 결정전역·창·mask 등 Attention 방식으로 결정

“고정 커널”은 학습하지 않는 상수라는 뜻이 아닙니다. 학습으로 바뀐 뒤, 추론 중에는 같은 커널을 여러 입력에 재사용한다는 뜻입니다. Attention도 Q/K/V 선형층의 가중치는 학습 후 고정되지만, 그 가중치로 만든 softmax(QKᵀ/√d)는 이미지마다 달라질 수 있습니다. 비교 대상은 파라미터의 유무가 아니라 정보 결합 계수가 만들어지는 방식입니다.

한편 CNN도 여러 층을 쌓고 공간 축소나 전역 평균을 사용하면 멀리 있는 정보를 모읍니다. “한 합성곱의 작은 창”을 “CNN 전체는 전체 이미지를 못 본다”로 확장하지 마세요. 반대로 창 단위 Attention까지 모두 처음부터 전역이라고 부를 수도 없습니다.

이것은 이미지 전체 모델이 아닌 1차원 위치 다섯 개·특징 두 개의 고정 예제입니다. 합성곱은 두 성분을 독립 처리하는 같은 커널 [0.25,0.5,0.25]를 써서 x₂ 주변을 계산합니다. 따라서 0.25·[0,1]+0.5·[1,1]+0.25·[−1,0]=[0.25,0.75]로 일정합니다. 일반 합성곱의 채널 혼합까지 재현하는 예는 아닙니다.

Attention은 Q=K=V라는 13장의 특수한 항등 투영을 사용합니다. x₀가 변하면 그 위치의 Key 점수와 Value가 함께 변하고, 행의 정규화 때문에 다른 위치의 계수도 달라집니다. 멀리 연결됐다고 더 좋은 결과를 보장하거나, 이 계수를 중요도의 인과적 설명으로 읽을 수는 없습니다. 이 예에는 학습·정확도·위치 임베딩·잔차가 없습니다.

17.4

공유는 CNN만의 성질일까?

17.4 같은 층을 쓰는 것과 위치를 아는 것

CNN은 위치가 달라도 같은 커널을 사용합니다. ViT도 패치 선형층과 토큰별 MLP, Q/K/V 투영을 위치마다 공유합니다. 따라서 “CNN은 공유, Transformer는 위치마다 별도 가중치”라는 대조는 틀립니다. 차이는 어떤 성분을 같은 방식으로 묶도록 구조가 제한하는가에 있습니다.

위치 정보가 없는 Self-Attention에서 토큰을 같은 순열로 재배열하면 출력도 대응해 재배열됩니다. 단, 위치값·mask 등의 조건도 따져야 합니다. ViT는 학습 가능한 위치 임베딩을 더하여 위치를 구분합니다. CNN은 공간 배열과 이웃 연결 자체가 위치 관계를 사용하며, stride·경계 padding 때문에 모든 이동에 정확히 같은 성질이 보장되는 것은 아닙니다. 이동 등변성은 이동 불변성과 다릅니다.

이 저장소의 PVT에는 별도 위치 임베딩이 없지만, 패치를 순서대로 격자로 복원하고 공간 축소 연산을 수행합니다. 그러므로 “위치 임베딩이 없으니 공간 관계가 전혀 없다”고 단정할 수 없습니다. 모델 이름보다 실제 연산 경로를 확인해야 하는 사례입니다.

17.5

같은 크기의 입력에서 추적하기

17.5 특징맵과 토큰은 완전히 다른 물건일까?

NCHW의 [B,C,H,W]는 공간 위치별 C차원 벡터 HW개로도 읽을 수 있습니다. flatten(2).transpose(1,2)는 이를 [B,HW,C]로 바꿉니다. 배열을 바꿨다는 사실만으로 새로운 정보가 생기거나 Attention이 수행되는 것은 아닙니다. 그 다음에 어떤 연산을 적용하는지가 중요합니다.

저장소 기본 모델 · 배치 B, CIFAR-10 32×32 · 표현 순서를 명시
경로중간 표현과 분류
ViT-Tiny[B,64,192] → CLS 포함 [B,65,192]를 12블록 동안 유지 → 기본 CLS 선택 → [B,10]
PVT-Tiny토큰 [B,64,64] → [B,16,128] → [B,4,320] → [B,1,512] → 정규화·평균 → [B,10]
ConvNeXt-TinyNCHW [B,96,8,8] → [B,192,4,4] → [B,384,2,2] → [B,768,1,1] → 평균·정규화 → [B,10]

PVT와 ConvNeXt는 모두 단계별로 공간을 줄이고 채널을 늘립니다. 따라서 피라미드는 CNN만의 전유물이 아닙니다. 현재 두 구현은 중간 다중 규모 특징을 외부에 반환하지 않는 분류용 모델이므로, 이 표만 보고 검출·분할까지 바로 실행할 수 있다고 생각하면 안 됩니다.

17.6

자원 비교의 단위

17.6 작은 모델이 반드시 빠른가?

항목무엇을 세는가?
파라미터학습 변수의 원소 수 · 입력 크기가 달라도 고정일 수 있음
MACs/FLOPs지정한 입력에서의 연산량 · 집계 관례와 포함 연산을 명시
메모리가중치뿐 아니라 활성값·기울기·optimizer 상태·임시 작업 공간
지연시간장비·배치·dtype·구현·측정 범위에 따른 실제 시간

특징 격자가 L×L, 채널 C, 커널 K일 때 같은 채널 수의 일반 합성곱 가중치는 K²C², MACs는 대략 L²K²C²입니다(편향 등 제외). 반면 전역 Attention의 QKᵀ와 AV는 토큰 T개와 전체 Head 차원 D에 대해 합계 약 2T²D MACs입니다. QKV·출력 투영과 MLP 비용은 이 식에 빠져 있으므로 이 두 부분식만으로 백본 전체의 비용 순위를 정할 수 없습니다.

예를 들어 L=8,C=192,K=3이면 합성곱 가중치는 331,776개, 해당 층은 21,233,664 MACs입니다. 별도로 ViT-Tiny의 T=65,D=192에서는 QKᵀ+AV가 1,622,400 MACs입니다. 서로 다른 연산 일부를 계산한 예이지 동등한 두 모델의 속도 비교가 아닙니다. MACs의 집계 기준도 함께 확인하세요.

P=4를 고정하고 입력 한 변을 32→64로 바꾸면 패치는 64→256개, CLS 포함 T는 65→257개입니다. Head당 표는 4,225→66,049칸으로 약 15.63배가 됩니다. CLS를 무시한 큰 T의 근사에서는 한 변 2배가 표 크기 약16배로 연결됩니다. 이것은 해상도별 비용을 생각하는 가정이며 저장소의 학습 CLI가 자동으로 64×64 모델을 구성한다는 뜻이 아닙니다.

프로젝트의 inference_ms_per_image는 준비된 배치의 forward 시간을 이미지 수로 나눈 값입니다. 데이터 읽기·전송을 포함한 서비스 응답시간이나 배치1 latency와 같지 않습니다. checkpoint_size_mb도 optimizer와 기록을 담는 파일 크기이며 순수 가중치 메모리가 아닙니다.

17.7

구현을 읽는 기준

17.7 코드에서 비교의 근거 찾기

실제 구현의 서로 다른 경로를 발췌
# backbone/ConvNeXt.py · Block
self.dwconv = nn.Conv2d(dim, dim, kernel_size=7, padding=3, groups=dim)
x = x.permute(0, 2, 3, 1)
x = input + self.drop_path(x)
# backbone/ViT.py · Attention
dots = torch.matmul(q, k.transpose(-1, -2)) * self.scale
attn = self.attend(dots)
out = torch.matmul(attn, v)
# backbone/PVT.py · Attention
x_ = self.sr(x_).reshape(B, C, -1).permute(0, 2, 1)

중간 정규화·투영 등은 생략한 발췌이며 독립 실행 코드가 아닙니다. 전체 경로는 16장, 13장, 15장에서 확인하세요. ConvNeXt와 PVT는 “CNN 또는 Transformer”라는 두 이름만으로 연산과 특징 구조를 전부 설명하기 어렵다는 구체적인 사례입니다.

17.8

다음 장의 실험 설계

17.8 같은 설정이면 언제나 공정할까?

같은 데이터 분할·입력·epoch·증강·optimizer를 쓰는 것은 좋은 출발점입니다. 하지만 동일 learning rate가 모든 구조에 동일하게 적합한 것은 아닙니다. 같은 recipe에서의 동작 비교와 각 모델을 같은 탐색 예산으로 조정한 성능 비교는 다른 실험입니다. 어느 질문을 택했는지 먼저 기록하세요.

작은 데이터에서 CNN을 기준으로 시작하거나, 전이 학습을 후보로 검토하는 것은 실험 전략이지 모든 경우의 우열 법칙이 아닙니다. 특히 이 프로젝트의 생성 함수는 사전학습 가중치를 자동으로 내려받지 않습니다. --quick 결과는 실행 확인에 사용하고, 최종 결론은 학습 조건·여러 seed·검증 선택·자원 제약을 함께 고려해야 합니다. 그 절차를 다음 장에서 실제 저장 파일과 연결합니다.

17.9

정리와 연습문제

17.9 비교 문장을 조건과 함께 쓰기

17장 핵심 정리

  • 합성곱의 학습 커널과 입력별 Attention 계수는 서로 다른 수준의 가중치입니다.
  • 지역 연결·피라미드·위치 공유는 모델 이름만으로 단정하지 않습니다.
  • 배열 변환과 정보 결합, 부분 연산량과 전체 모델 속도를 구분합니다.
  • 구조 비교에는 학습·데이터·평가 조건이 따라야 합니다.
Q1. x₀를 바꿔도 합성곱 출력이 같은 이유는?

지금 계산하는 x₂의 한 층 커널은 x₁·x₂·x₃만 연결하기 때문입니다. 깊은 CNN 전체가 x₀를 이용하지 못한다는 뜻은 아닙니다.

Q2. Attention의 Head 수가 같으면 메모리도 같은가?

토큰 수·Head 차원·배치·dtype·구현을 함께 봐야 합니다. 전역 가중치 표의 크기만 해도 배치×Head×T²입니다.

Q3. 빠른 1 epoch 비교로 모델 계열의 우열을 결론 낼 수 있을까?

아닙니다. 짧은 실행 조건에서의 결과이며, 충분한 학습·동일한 선택 기준·반복·자원 보고가 필요합니다.
