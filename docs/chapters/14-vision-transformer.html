제5부Transformer선수 지식: 13장

제14장 · 이미지를 패치의 열로 읽다Vision Transformer

13장에서 세 벡터 사이의 Attention을 계산했습니다. 이번에는 32×32 이미지 → 4×4 패치 64개 → [CLS]를 포함한 토큰 65개 → Encoder → 10개 분류 점수로 이어지는 실제 경로를 따라갑니다. 패치 크기를 바꾸며 계산량의 변화를 확인하고, 논문 속 ViT와 이 저장소의 실습 모델을 구분합니다.

학습 목표

  • 패치 크기 P에서 토큰 수 N과 패치 벡터 길이 3P²을 계산할 수 있습니다.
  • 선형 투영, [CLS], 위치 임베딩의 역할을 구분할 수 있습니다.
  • Encoder의 Attention·MLP·잔차 연결을 코드에서 찾을 수 있습니다.
  • 원 논문 결과와 CIFAR-10의 짧은 직접 학습 결과를 혼동하지 않을 수 있습니다.
14.1

논문 리뷰 · 문제와 제안

14.1 합성곱 없이 이미지를 분류할 수 있을까?

Alexey Dosovitskiy et al.ICLR 2021 · arXiv 2020

An Image is Worth 16x16 Words

논문은 이미지를 일정한 크기의 패치로 나누고, 각 패치를 선형 임베딩해 Transformer Encoder에 넣는 단순한 구성을 연구했습니다. 핵심 결과는 대량의 이미지로 사전학습한 뒤 다른 데이터셋에 전이했을 때 강한 이미지 분류 성능을 보였다는 것입니다. 패치만 자르면 어떤 작은 데이터셋에서도 CNN보다 낫다는 주장은 아닙니다.

원 논문 보기 ↗

CNN은 같은 필터를 여러 위치에 공유하고 가까운 픽셀을 먼저 묶는 구조적 가정이 있습니다. ViT는 고정 패치를 만든 뒤에는 토큰 사이의 관계를 Attention으로 학습합니다. 원 논문도 이런 inductive bias의 차이와 학습 데이터 규모의 영향을 함께 논의합니다. 따라서 구조 비교는 모델·데이터·학습 조건을 분리해서 읽어야 합니다.

14.2

실습 14.1 · 픽셀에서 패치로

14.2 패치가 작아지면 토큰은 몇 개가 될까?

아래 32×32 그림은 원리를 보여주기 위해 코드로 그린 도식이며 실제 CIFAR-10 사진이 아닙니다. 패치 크기를 고른 뒤 그림의 한 칸을 선택하세요. 원본 픽셀을 겹치지 않게 나누는 모습을 확인할 수 있습니다.

패치 크기 P
설명용 32×32 픽셀 그림 · 선은 패치 경계
선택한 패치4행 4열

x=12–15, y=12–15

RGB 픽셀을 펼치면 48개 숫자
이미지 패치 N64(32 ÷ P)²
패치 원본 벡터483 × P²
[CLS] 포함 토큰65N + 1
Head당 Attention 칸4,225(N + 1)²

RGB 패치 하나에는 P×P×3개의 픽셀 성분이 있습니다. Rearrange는 이를 한 줄로 펴고, 다음 선형층이 모델 차원으로 바꿉니다. 패치를 작게 하면 더 세밀한 단위를 유지하지만 토큰 수 N이 늘고, 각 Head의 Attention 표는 (N+1)²로 빠르게 커집니다. +1은 [CLS] 토큰입니다.

14.3

모양을 따라가기

14.3 패치 벡터를 같은 길이의 토큰으로 바꾼다

이 저장소의 vit_tiny는 기본 P=4에서 각 패치를 48개 숫자로 펼친 후, 학습 가능한 선형층으로 길이 192의 patch embedding을 만듭니다. 64개 패치 토큰 앞에 학습 가능한 [CLS] 토큰 하나를 붙입니다. 마지막으로 토큰마다 길이 192의 position embedding을 더합니다. 위치 임베딩은 픽셀 위치를 출력 결과에 단순히 추가하는 것이 아니라, Encoder에 들어가기 전 토큰 벡터에 더하는 값입니다.

입력[B, 3, 32, 32]RGB 이미지
패치 펼침[B, 64, 48]64개 × 3·4²
선형 투영[B, 64, 192]패치 임베딩
[CLS] + 위치[B, 65, 192]Encoder 입력

위 모양은 기본 P=4를 고정한 예입니다. 앞의 패치 실습에서 크기를 바꾸더라도 실제 vit_tiny() 인스턴스는 자동으로 재설정되지 않습니다. 모델을 새 패치 크기로 만들 때만 토큰 수와 위치 임베딩 크기가 함께 바뀝니다.

14.4

같은 블록을 반복

14.4 Encoder는 무엇을 12번 반복하는가?

vit_tiny의 depth=12는 Encoder 블록 12개를 뜻합니다. 각 블록은 먼저 LayerNorm 뒤 Multi-Head Attention을 적용하고 입력을 더합니다. 이어 LayerNorm 뒤 두 선형층과 GELU로 이뤄진 MLP를 적용하고 다시 입력을 더합니다. 덧셈은 9장에서 살펴본 residual connection과 같은 계열의 우회 경로입니다.

토큰 열 X[B, 65, 192]
→
LN → Attention3 Heads · 토큰 관계
→
+ X첫 잔차 연결
→
LN → MLP192 → 768 → 192
→
+ 입력둘째 잔차 연결

Attention은 토큰 사이의 정보를 섞고, MLP는 각 토큰의 특징 차원에 동일한 층을 적용합니다. 블록을 지나도 토큰의 개수와 모델 차원은 [65,192]로 유지됩니다. 실제 코드에서는 PreNorm과 FeedForward가 이 순서를 구현합니다.

14.5

마지막 표현 선택

14.5 왜 [CLS]가 맨 앞에 있는가?

분류를 위한 학습 가능한 토큰을 패치 열 앞에 붙이면, 이 토큰도 다른 패치와 Attention으로 정보를 주고받습니다. 마지막 블록의 [CLS] 표현을 가져와 분류층에 넣는 것이 이 저장소의 기본 경로입니다.

[CLS]패치 1패치 2…패치 64

[CLS]의 마지막 표현 x[:, 0]만 꺼내 LayerNorm과 선형 분류층에 전달합니다.

입력 표현[B, 192]분류 점수[B, 10]

코드는 pool='mean'도 허용합니다. 이 경우 x.mean(dim = 1)이므로 [CLS]를 포함한 65개 토큰 전체를 평균합니다. 이는 일부 구현에서 [CLS]를 제외하고 패치만 평균하는 방식과 다릅니다. 어느 방식이 좋은지 이 페이지의 그림만으로 결론 내릴 수 없고, 동일한 실험 조건에서 비교해야 합니다.

14.6

프로젝트의 백본 목록

14.6 Tiny·Small·Base·Large는 무엇이 다른가?

아래 값은 논문의 모델 명칭을 그대로 재현한 표가 아니라 backbone/ViT.py에 정의된 이 프로젝트의 생성 함수입니다. 기본 입력은 모두 32×32, 패치 크기는 4, 출력 클래스는 10개입니다. 이름이 비슷해도 논문 체크포인트나 사전학습 가중치가 자동으로 들어오지 않습니다.

생성 함수차원 D블록 수Head 수MLP 중간 차원
vit_tiny192123768
vit_small3841261,536
vit_base76812123,072
vit_large1,02424164,096

이 구현의 dim_head=64 기본값 때문에 Head 수를 늘리면 Q·K·V의 전체 내부 차원도 함께 커집니다. 작은 장비에서는 먼저 vit_tiny로 동작을 확인하고, 모델 간 결과를 비교할 때는 학습 시간·메모리·동일한 학습 설정을 기록하세요.

14.7

실제 프로젝트 코드

14.7 그림의 화살표가 코드에서는 어느 줄인가?

backbone/ViT.py의 생성·순전파 경로를 발췌했습니다. 오른쪽 설명을 누르면 패치 만들기부터 분류까지 해당 줄이 강조됩니다.

backbone/ViT.py · ViT
Rearrange('b c (h p1) (w p2) -> b (h w) (p1 p2 c)', p1 = patch_height, p2 = patch_width)
nn.Linear(patch_dim, dim)
self.pos_embedding = nn.Parameter(torch.randn(1, num_patches + 1, dim))
self.cls_token = nn.Parameter(torch.randn(1, 1, dim))
x = self.to_patch_embedding(img)
cls_tokens = repeat(self.cls_token, '1 1 d -> b 1 d', b = b)
x = torch.cat((cls_tokens, x), dim = 1)
x += self.pos_embedding[:, :(n + 1)]
x = self.transformer(x)
x = x.mean(dim = 1) if self.pool == 'mean' else x[:, 0]
return self.mlp_head(x)

이 발췌는 서로 다른 메서드의 핵심 줄을 계산 흐름 순서로 모은 것으로, 그대로 독립 실행하는 코드 블록은 아닙니다. [CLS] 추가 뒤의 x는 [B,65,192], 마지막 분류층의 출력은 [B,10]입니다. 자세한 Attention 내부 계산은 13장 실제 코드를 함께 보세요.

14장 핵심 정리

  • 32×32 RGB 이미지를 P=4로 나누면 64개 패치, 패치당 48개 숫자가 됩니다.
  • 선형 투영으로 길이 192인 토큰을 만들고 [CLS]와 위치 임베딩을 더해 65개를 Encoder에 보냅니다.
  • Encoder는 Attention·MLP와 잔차 연결을 12번 반복하며, 기본 분류 경로는 마지막 [CLS] 표현을 씁니다.
  • 작은 데이터의 빠른 직접 학습 결과는 대규모 사전학습을 다룬 원 논문 결과의 재현이 아닙니다.
