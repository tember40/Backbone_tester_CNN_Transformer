제15장 · 토큰을 줄이며 여러 크기의 특징을 남기다Pyramid Vision Transformer

ViT는 같은 크기의 토큰 열을 끝까지 처리했습니다. PVT는 이미지를 네 단계의 점점 작은 공간 격자로 바꾸고, 앞 단계의 많은 토큰을 다룰 때는 Query는 유지하고 Key·Value 쪽만 줄이는 Attention을 사용합니다. 이 장에서는 논문의 목적과 이 저장소의 CIFAR-10 분류 구현을 구분해 읽습니다.

학습 목표

  • 네 단계에서 해상도·토큰 수·채널 수가 어떻게 바뀌는지 설명할 수 있습니다.
  • Spatial-Reduction Attention의 Query 수와 Key/Value 수를 따로 계산할 수 있습니다.
  • 224×224 설정의 축소 비율이 32×32에서 왜 그대로 맞지 않는지 설명할 수 있습니다.
  • 원 논문의 다중 규모·분류 방식과 현재 저장소의 실제 출력 범위를 구분할 수 있습니다.
15.1

논문 리뷰 · 문제와 제안

15.1 이미지 한 장의 분류를 넘어서는 백본

Wenhai Wang et al.ICCV 2021

Pyramid Vision Transformer: A Versatile Backbone for Dense Prediction without Convolutions

원 논문은 단일 규모 토큰 열을 쓰는 ViT를 검출·분할처럼 위치별 예측이 필요한 작업에 적용하기 어려운 점에 주목했습니다. 제안한 두 핵심은 단계마다 공간 크기를 줄여 여러 해상도의 특징을 만들기와 Key·Value의 공간 수를 줄여 Attention 비용 낮추기입니다. 논문은 분류뿐 아니라 검출·분할에도 평가를 제시합니다.

원 논문 보기 ↗

여기서 dense prediction은 이미지 전체에 점수 하나를 내는 분류와 달리, 물체의 위치나 픽셀별 범주를 예측하는 일을 말합니다. 작은 물체와 큰 물체를 함께 보려면 서로 다른 공간 크기의 특징이 유용합니다. 다만 이 저장소의 실행 경로는 CIFAR-10 분류만 수행하므로, 논문의 검출·분할 성능을 이 페이지에서 재현하지는 않습니다.

15.2

하나의 열에서 네 크기의 격자로

15.2 앞에서는 촘촘하게, 뒤에서는 넓게 읽는다

첫 단계는 입력을 4×4 패치로 나눕니다. 다음 세 단계는 직전 특징맵을 각각 2×2 단위로 묶어 공간 가로·세로를 절반으로 줄입니다. 대신 채널은 64 → 128 → 320 → 512로 늘어납니다. 이것이 progressive shrinking입니다. 각 단계 내부의 Encoder는 토큰 수를 유지하고, 단계 사이 PatchEmbed가 격자 크기를 바꿉니다.

입력32×32×3
→
1단계 · /48×8×6464개 토큰
→
2단계 · /84×4×12816개 토큰
→
3단계 · /162×2×3204개 토큰
→
4단계 · /321×1×5121개 토큰

논문의 대표 224×224 입력이라면 같은 단계가 56×56, 28×28, 14×14, 7×7 격자가 됩니다. 즉 네 단계라는 구조는 같아도 각 단계에 남는 공간 정보의 양은 입력 크기에 크게 좌우됩니다. 특히 CIFAR-10의 마지막 1×1 단계에서는 위치별 예측을 위한 격자가 더는 남지 않습니다.

15.3

실습 15.1 · Q와 K/V를 분리해서 보기

15.3 어느 단계에서 몇 개를 비교할까?

입력 크기를 고르고 1~4단계를 누르세요. 왼쪽은 모든 위치에서 만드는 Query, 오른쪽은 축소 후 Key·Value의 위치를 그린 도식입니다. 큰 격자는 최대 8×8칸으로 축약 표시하므로 정확한 수는 아래 지표를 읽어야 합니다.

32×32 CIFAR-10 조정 설정

1단계 · 8×8 특징 격자

Query는 64곳 모두에서 만들고, Key·Value는 2×2 공간 축소 뒤 16곳에서 만듭니다.

채널 / Head / 블록
64 / 1 / 2
SRA 축소 비율 r
2
Query · 모든 위치8×8 = 64
→
Key / Value · 축소 후4×4 = 16
Query 수64
Key/Value 수16
Head당 SRA 표1,024
축소 전 표4,096

축소 후에도 Key·Value 위치가 16개 남아 여러 위치를 비교할 수 있습니다.

위 수는 Head 하나의 Attention 표 칸 수이며 모델 전체 FLOPs나 메모리 사용량이 아닙니다. 여러 Head, 블록 반복, 선형 투영과 Conv2d 축소의 비용도 추가됩니다. `32×32 · 논문 비율 그대로`는 문제를 보여주는 비교용이며 현재 프로젝트의 기본 실행 설정은 아닙니다.

15.4

공간 축소 Attention

15.4 Query는 남기고 Key·Value만 줄인다

13장의 일반 Self-Attention은 Query N개와 Key N개를 비교해 N×N 표를 만듭니다. PVT의 Spatial-Reduction Attention (SRA)은 Query는 원래 N개로 두고, Key·Value를 만들 입력을 공간상 r×r 묶음으로 축소합니다. 정사각 격자 H×W가 r로 나누어떨어지면 Key·Value 위치는 (H/r)×(W/r)개입니다. 따라서 표는 NQ×NKV가 됩니다.

Q: N = H·W→K/V: N / r²→Attention: N × (N / r²)

이 코드의 self.sr는 kernel_size=r, stride=r인 Conv2d입니다. 여러 이웃 토큰을 학습 가능한 방식으로 합쳐 K/V 입력을 만들고 LayerNorm을 적용합니다. 이는 r=1일 때는 실행되지 않습니다. 논문 제목의 “without Convolutions”는 CNN 블록을 백본의 주 연산으로 쌓지 않는다는 취지로 읽어야 하며, 코드에 Conv2d 연산이 전혀 없다는 뜻은 아닙니다.

15.5

작은 이미지에서 생기는 예외

15.5 224용 비율을 32에 그대로 옮기면?

논문의 224×224 규모에서 단계별 격자는 56·28·14·7이고 축소 비율은 8·4·2·1입니다. 모두 K/V 격자가 7×7=49곳으로 남습니다. 같은 비율을 CIFAR-10의 8·4·2·1 격자에 쓰면 매 단계 K/V가 1곳이 됩니다. 여러 위치 중 고르는 Attention을 살펴보려는 학습 목적에는 맞지 않습니다.

32×32 설정1단계 K/V2단계 K/V3단계 K/V4단계 K/V
224용 r=[8,4,2,1] 그대로1111
현재 프로젝트 r=[2,1,1,1]161641

이번 수정은 pvt_tiny(img_size=32) 등 생성 함수의 기본값에만 적용됩니다. 224 입력의 원래 비율은 그대로 유지하고, sr_ratios를 명시하면 사용자가 덮어쓸 수 있습니다. 마지막 1×1 단계의 K/V=1은 피라미드 구조상 피할 수 없습니다. 이 조정은 교육용 CIFAR-10 변형이지 논문 결과를 그대로 재현했다는 뜻이 아닙니다.

15.6

실제 프로젝트 코드

15.6 격자 축소는 어느 줄에서 일어나는가?

backbone/PVT.py에서 PatchEmbed와 SRA, CIFAR용 비율을 발췌했습니다. 오른쪽 설명을 눌러 계산 그림과 대응해 보세요.

backbone/PVT.py · 핵심 경로
self.proj = nn.Conv2d(in_chans, embed_dim, kernel_size=patch_size, stride=patch_size)
x = self.proj(x).flatten(2).transpose(1, 2)
q = self.q(x).reshape(B, N, self.num_heads, C // self.num_heads).permute(0, 2, 1, 3)
self.sr = nn.Conv2d(dim, dim, kernel_size=sr_ratio, stride=sr_ratio)
x_ = x.permute(0, 2, 1).reshape(B, C, H, W)
x_ = self.sr(x_).reshape(B, C, -1).permute(0, 2, 1)
kv = self.kv(x_).reshape(B, -1, 2, self.num_heads, C // self.num_heads).permute(2, 0, 3, 1, 4)
attn = (q @ k.transpose(-2, -1)) * self.scale
attn = attn.softmax(dim=-1)
return x.mean(dim=1) # Global Average Pooling
sr_ratios = kwargs.pop("sr_ratios", [2, 1, 1, 1] if img_size == 32 else [8, 4, 2, 1])

이 발췌는 서로 다른 클래스·메서드의 줄을 학습 순서로 모았으므로 독립 실행 코드가 아닙니다. r=1일 때는 self.sr 대신 전체 x에서 K/V를 만듭니다. 자세한 분기와 네 단계 반복은 상단의 실제 코드 링크에서 확인할 수 있습니다.

15.7

논문과 저장소를 분리해서 읽기

15.7 지금 코드가 논문 전체를 재현하지는 않는다

원 논문은 각 단계의 특징 피라미드 F1~F4를 검출·분할 헤드에 제공하고, 단계별 위치 임베딩을 더합니다. 분류에서는 마지막 단계에 학습 가능한 분류 토큰을 붙입니다. 현재 저장소의 backbone/PVT.py는 중간 단계에서 2D 특징맵으로 잠시 바꾸지만 F1~F4를 외부로 반환하지 않고, 학습 가능한 위치 임베딩·[CLS] 토큰도 두지 않습니다. 대신 마지막 토큰 평균을 선형 분류층에 넣습니다.

항목원 논문 PVT현재 저장소
다중 규모 출력F1~F4를 다운스트림 작업에 활용중간 단계에서 만들지만 공개 반환값은 분류 점수
위치 정보단계별 위치 임베딩별도 위치 임베딩 매개변수 없음
분류 집계마지막 단계 [CLS] 토큰마지막 토큰 평균, 32×32에서는 1개 평균
평가 범위ImageNet 분류와 검출·분할CIFAR-10 분류 실행

따라서 이 프로젝트로 피라미드와 SRA의 계산 원리는 확인할 수 있지만, 현재 명령만으로 논문의 검출·분할 수치를 재현할 수는 없습니다. 앞으로 그런 작업을 추가하려면 중간 특징맵을 반환하는 백본 인터페이스, 검출·분할 헤드, 해당 데이터와 평가 절차가 필요합니다.

15.8

직접 실행 후 읽기

15.8 작은 데이터의 결과를 과장하지 않기

cifar10-lab train --model pvt_tiny --quick은 저장소의 모델 등록을 통해 32×32 입력과 조정된 SRA 비율로 짧은 학습을 실행합니다. 이는 파이프라인과 분류 출력이 작동하는지 보는 실습입니다. 논문의 ImageNet·검출·분할 실험과 데이터, 출력 헤드, 학습 절차가 모두 다릅니다.

ViT와 PVT를 비교할 때는 정확도만 적지 말고 같은 분할·epoch·증강·최적화 조건, 모델 크기, 학습 시간, 여러 시드를 함께 기록하세요. 특히 PVT의 마지막 단계가 CIFAR-10에서는 1×1인 점과 현재 구현이 위치 임베딩을 생략한 점을 비교 해석에 포함해야 합니다.

정리와 연습문제

15.9 어느 수가 줄고, 무엇은 남는가?

15장 핵심 정리

  • PVT는 네 단계에서 공간 격자를 줄이고 채널을 늘려 여러 크기의 특징을 만듭니다.
  • SRA는 Query 위치를 유지하며 K/V 위치를 축소해 Head당 Attention 표를 NQ×NKV로 만듭니다.
  • 32×32에는 원래 r=[8,4,2,1]이 모든 K/V를 1개로 만들어, 이 프로젝트는 [2,1,1,1]로 조정합니다.
  • 현재 저장소의 PVT는 분류용 변형이며 원 논문의 위치 임베딩·[CLS]·검출/분할 출력까지 재현하지 않습니다.
