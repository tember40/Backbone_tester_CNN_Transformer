    각 입력에 가중치를 곱합니다.

  2. 2

  3. 3
    0을 기준으로 출력합니다.

    가중합이 0 이상이면 1, 0보다 작으면 0을 출력합니다.

z = x₁w₁ + x₂w₂ + b

→
계단 함수

ŷ = 1 if z ≥ 0, else 0

기호에서 숫자로 읽기

x는 관찰한 입력, w와 b는 학습으로 바꿀 값입니다. 정답 y와 예측 ŷ는 다릅니다. 점수 z는 두 예측 영역 중 어느 쪽인지 정할 뿐, 이 모델에서는 확률이 아닙니다. z=2라고 해서 정답일 확률이 200%인 것은 아닙니다.

예를 들어 x=(1, 0.5), w=(0.8, −0.4), b=0.1이면 기여량은 0.8과 −0.2, 편향은 0.1입니다. 합계 z=0.7이므로 예측은 1입니다. 두 번째 가중치가 음수라는 것은 x₂를 늘릴 때 점수가 내려간다는 뜻이지, 두 번째 입력이 쓸모없다는 뜻이 아닙니다.

입력 단위를 100배로 바꾸고 해당 가중치를 100분의 1로 줄이면 같은 점수를 만들 수 있습니다. 따라서 가중치의 절댓값만으로 서로 다른 단위의 입력 중요도를 비교하지 않습니다.

1.4 수식을 실제 코드로 옮기기

아래 코드는 `cifar10_lab/foundations.py`에서 실제로 사용되는 클래스입니다. 해설을 선택하면 관련 코드가 강조됩니다.

cifar10_lab/foundations.py
class ClassicPerceptron:
    """A classic binary perceptron with a hard step activation."""

    def __init__(self, input_features=2, learning_rate=0.1):
        if input_features < 1:
            raise ValueError("input_features must be at least 1.")
        if learning_rate <= 0:
            raise ValueError("learning_rate must be greater than zero.")
        self.learning_rate = learning_rate
        self.weights = torch.zeros(input_features, dtype=torch.float32)
        self.bias = 0.0
        self.history = []

    def score(self, features):
        return features @ self.weights + self.bias

    def predict(self, features):
        return (self.score(features) >= 0).to(torch.long)

    def fit(self, features, targets, epochs=10):
        if features.ndim != 2 or features.shape[1] != len(self.weights):
            raise ValueError("features must have shape [samples, input_features].")
        if len(features) != len(targets):
            raise ValueError("features and targets must contain the same number of samples.")
        if epochs < 1:
            raise ValueError("epochs must be at least 1.")

        self.history = []
        step = 0
        for epoch in range(1, epochs + 1):
            for sample_index, (sample, target) in enumerate(zip(features, targets)):
                prediction = int(self.predict(sample).item())
                target_value = int(target.item())
                error = target_value - prediction
                self.weights += self.learning_rate * error * sample
                self.bias += self.learning_rate * error
                self.history.append(
                    PerceptronSnapshot(
                        step=step,
                        epoch=epoch,
                        sample_index=sample_index,
                        weights=self.weights.clone(),
                        bias=float(self.bias),
                        prediction=prediction,
                        target=target_value,
                        error=error,
                    )
                )
                step += 1
        return self.history

`features @ self.weights + self.bias`는 앞에서 본 `x₁w₁ + x₂w₂ + b`를 입력 차원 수와 관계없이 계산할 수 있도록 벡터 연산으로 표현한 것입니다.

이미지 분류 목록의 ‘perceptron’과 구분하기

여기서 읽은 ClassicPerceptron은 0/1 계단 함수와 오답 갱신 규칙을 사용합니다. 반면 backbone/Perceptron.py의 이미지 기준 모델은 3×32×32 픽셀을 3,072개 값으로 펼쳐 10개 점수(logits)를 만드는 nn.Linear입니다. 그 점수는 학습 시 CrossEntropyLoss에 전달하며, 이 장의 수동 갱신 규칙으로 학습하는 것이 아닙니다.

갱신 규칙과 그림을 함께 읽기

오차는 e=y−ŷ이며, 학습률 η를 사용해 Δw=ηex, Δb=ηe를 계산합니다. 새 파라미터는 w+Δw, b+Δb입니다. 이 규칙의 e는 미분으로 구한 기울기가 아니라 정답과 0/1 예측의 차이입니다. 미분을 이용하는 학습은 3장에서 구분합니다.

AND 기본값에서 첫 표본 (0,0)의 정답은 0입니다. 처음에는 z=0이므로 규칙에 따라 ŷ=1, e=−1입니다. η=0.1일 때 두 입력이 0이라 Δw=(0,0)이지만 Δb=−0.1이 되어, 처리 후 점수는 −0.1, 예측은 0이 됩니다. 가중치가 둘 다 0이면 직선의 방향이 없으므로 첫 단계 그림에는 경계선 대신 한 예측 영역만 보입니다.

표의 ‘예측 / 정답’과 학습 기록은 갱신 전 예측으로 오차를 계산한 값입니다. 배경·✓/×·현재 정확도는 갱신 후 파라미터로 네 점을 다시 평가한 결과입니다. 한 점을 고치면 다른 점의 예측도 바뀔 수 있으므로, 두 시점의 숫자가 달라도 오류는 아닙니다. 여기의 정확도는 같은 네 학습 표본에 대한 값이며 새 데이터에 대한 성능이 아닙니다.

먼저 AND에서 첫 네 단계를 예상하고 표와 대조하세요. 이후 XOR로 바꿔 20 epoch를 진행해도 오답이 남는 이유를 생각해 보세요. 모든 점을 맞힐 수 없는 이유는 다음 장에서 탐색 결과가 아닌 부등식으로 확인합니다.

AND·OR·NAND

두 클래스를 직선 하나로 분리할 수 있어 학습이 수렴합니다.

XOR

같은 클래스가 대각선에 놓여 직선 하나로 모두 분리할 수 없습니다.
