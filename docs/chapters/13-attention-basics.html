제13장 · 각 위치가 무엇을 참고할지 정하다Attention 기초

합성곱은 작은 이웃을 같은 필터로 읽었습니다. Self-Attention은 한 토큰이 다른 토큰들을 얼마나 참고할지 입력에 따라 계산합니다. 이 장에서는 세 개의 작은 벡터만 사용해 점수 → 가중치 → 값의 가중합을 직접 따라가 봅니다. 다음 장에서 이 토큰들이 이미지 패치가 됩니다.

학습 목표

  • Query·Key·Value가 점수와 출력에 맡는 역할을 구분할 수 있습니다.
  • 스케일된 내적, 행별 softmax, Value 가중합을 숫자로 추적할 수 있습니다.
  • Attention 행렬이 토큰 수 N에 따라 N×N으로 커지는 이유를 설명할 수 있습니다.
  • 이 저장소의 ViT 코드에서 여러 Head와 [CLS] 토큰의 위치를 찾을 수 있습니다.
13.1

출발점

13.1 Attention은 이미지에서 시작하지 않았다

Ashish Vaswani et al.NeurIPS 2017

Attention Is All You Need

원 논문은 주로 기계 번역을 다루며, 순서 속 각 위치가 다른 위치의 정보를 모으는 scaled dot-product attention과 여러 Head를 제시했습니다. 이미지 모델 ViT는 이 계산을 이미지 패치의 열에 적용합니다. Attention의 수식과 이미지 적용은 서로 다른 연구 단계입니다.

원 논문 보기 ↗

“어디를 본다”는 표현은 모든 토큰에 같은 한 번의 고정 연결을 만든다는 뜻이 아닙니다. 현재 입력에서 만들어진 Query와 Key의 유사도를 토대로 토큰마다 다른 가중치를 계산한다는 뜻입니다. Attention 가중치가 곧 모델의 완전한 판단 근거라는 의미로 해석하지는 마세요.

13.2

입력의 단위

13.2 먼저 배열을 토큰의 열로 본다

언어 모델의 토큰은 단어나 부분 단어일 수 있고, 이미지 ViT의 토큰은 일정한 이미지 패치를 벡터로 바꾼 것입니다. 이 장의 실습에서는 위치 A·B·C를 실제 사진이 아닌 2차원 숫자 벡터 세 개로 줄여 계산을 보여줍니다. 각 토큰이 어떤 위치의 정보를 더 많이 모으는지 확인하는 데 집중하세요.

토큰실습 벡터그림으로 생각하면
A[1, 0]첫 번째 패치
B[0, 1]두 번째 패치
C[1, 1]두 성분을 모두 가진 패치

실제 backbone/ViT.py에서는 32×32 이미지를 4×4 패치로 나눕니다. 패치가 8×8=64개이고 [CLS] 토큰을 앞에 하나 붙여 65개 토큰이 Attention에 들어갑니다. 이 계산은 다음 장에서 이미지 위에 직접 표시합니다.

13.3

역할 나누기

13.3 Query는 묻고, Key는 비교되고, Value는 전달된다

한 토큰의 Query (Q)는 “어떤 정보와 잘 맞는가”를 묻는 벡터입니다. 모든 토큰의 Key (K)와 Query를 비교해 점수를 만들고, 그 점수로 계산한 가중치를 각 Value (V)에 곱해 더합니다. 같은 입력에서 Q·K·V를 만들지만, 실제 모델에서는 서로 다른 학습 가능한 선형 변환의 출력입니다.

입력 토큰Q × KT누구와 맞는가?softmax얼마나 참고할까?가중치 × V무슨 정보를 모을까?새 표현

아래 숫자 실습은 계산을 단순화하려고 Q=K=V=[토큰 벡터]로 둡니다. 이는 세 선형 변환이 항등 변환인 특수한 예시일 뿐, 실제 모델의 Q·K·V가 언제나 같다는 뜻이 아닙니다.

13.4

첫 단계 · 유사도

13.4 내적을 √dk로 나눈다

점수 S = QKT / √dk→가중치 A = softmax(S)

실습 벡터의 Key 차원은 2이므로 √2로 나눕니다. 예를 들어 Query A=[1,0]과 Key C=[1,1]의 내적은 1이고, 스케일한 점수는 약 0.707입니다. 차원이 커질 때 내적 크기가 과하게 커져 softmax가 한쪽으로 치우치는 일을 완화하려는 조정입니다. 0.707은 확률이 아니라 softmax 이전 점수입니다.

13.5

실습 13.1 · 한 행씩 읽기

13.5 점수에서 Value 가중합까지

Query를 바꾸면 표에서 해당 행의 점수·가중치·출력이 함께 바뀝니다. 각 행의 softmax는 세 Key 방향으로 합이 1이 됩니다. 먼저 A를 선택한 채 숫자를 읽고 B·C로 바꿔 보세요.

전체 Attention 가중치: 행은 Query, 열은 Key
Q \ KABC
① Q·K 내적 / √2—
② softmax 가중치——
③ Σ 가중치 × V——

색이 진할수록 해당 Query가 그 Key의 Value를 더 많이 반영한다는 뜻입니다. 이 실습에서 C는 A와 B의 성분을 모두 가지므로 여러 Query에서 높은 점수를 얻기 쉽습니다. 표는 가중치이지 원본 이미지의 주목 지도나 학습된 ViT의 실제 Attention 결과가 아닙니다.

13.6

여러 관점으로 반복

13.6 Multi-Head는 한 표를 복사하는가?

아닙니다. Head마다 Q·K·V의 서로 다른 성분을 사용하므로 각자 다른 가중치 표를 만들 수 있습니다. 이 저장소의 vit_tiny는 heads=3, dim_head=64이며 내부 Q·K·V를 [배치, 3, 토큰, 64] 모양으로 나눕니다. Head 출력을 다시 합친 뒤 선형 변환으로 모델 차원 192에 돌려놓습니다.

토큰이 N개라면 Head 하나의 점수·가중치 행렬에는 N×N개 칸이 있습니다. 이 프로젝트의 기본 설정은 패치 64개+[CLS] 1개이므로 Head마다 65×65=4,225칸입니다. Head가 3개라면 한 층에서 이 크기의 표가 3개 생깁니다. 이미지가 커지거나 패치가 작아져 N이 늘면 이 부분의 저장·계산 부담도 커집니다.

13.7

실제 프로젝트 코드

13.7 수식이 어느 줄에서 실행되는가?

아래는 backbone/ViT.py의 Attention 경로에서 필요한 줄을 순서대로 발췌했습니다. Head 분리, 스케일, softmax, Value 합산을 클릭하며 앞의 세 단계와 대응해 보세요.

backbone/ViT.py · Attention
self.scale = dim_head ** -0.5
self.to_qkv = nn.Linear(dim, inner_dim * 3, bias = False)
qkv = self.to_qkv(x).chunk(3, dim = -1)
q, k, v = map(lambda t: rearrange(t, 'b n (h d) -> b h n d', h = self.heads), qkv)
dots = torch.matmul(q, k.transpose(-1, -2)) * self.scale
attn = self.attend(dots)
attn = self.dropout(attn)
out = torch.matmul(attn, v)
out = rearrange(out, 'b h n d -> b n (h d)')
return self.to_out(out)

self.attend는 마지막 축에 적용하는 nn.Softmax(dim = -1)입니다. 따라서 각 Query 행에서 모든 Key에 대한 가중치 합이 1이 됩니다. 추론 시 Dropout은 꺼지지만, 학습 시에는 softmax 뒤 Dropout이 적용되어 개별 숫자 예시와 달라질 수 있습니다.

13.8

다음 장으로

13.8 이미지는 어떻게 토큰이 되는가?

Attention 수식은 토큰의 순서나 이미지의 위·아래·좌·우를 스스로 알지 못합니다. 이 저장소의 ViT는 이미지를 패치로 펼쳐 선형층에 넣고, 앞에 학습 가능한 [CLS] 토큰을 붙인 다음 pos_embedding을 더합니다. 이 위치 정보가 있어야 같은 숫자 토큰이라도 어디서 왔는지 구별할 수 있습니다.

토큰 추가[CLS] 1개 → 전체 65개
위치 정보학습 가능한 위치 임베딩을 더함
분류기본 pool='cls'에서 [CLS]의 마지막 표현 사용

  • Q와 K의 내적을 √dk로 스케일해 토큰 쌍의 점수를 만듭니다.
