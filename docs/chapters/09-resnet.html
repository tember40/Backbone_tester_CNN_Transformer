제9장 · ResNet과 확장 모델ResNet

VGG는 층을 더 깊게 쌓는 방법을 정돈했습니다. 그런데 깊이가 계속 늘면 학습 오차조차 악화되는 경우가 있습니다. ResNet은 입력을 다음 층으로 건너 보내고, 층들이 입력에 더할 변화량을 학습하게 합니다. 이 장에서는 그 덧셈이 코드와 특징맵에서 어떻게 성립하는지 확인합니다.

학습 목표

  • 깊은 plain network의 degradation을 과적합과 구분할 수 있습니다.
  • 잔차 연결의 덧셈, 차원 일치 조건, 투영 shortcut을 설명할 수 있습니다.
  • ResNet18·34·50의 블록 구성과 32×32 입력의 단계별 크기를 추적할 수 있습니다.
  • ResNeXt의 그룹 수와 Wide ResNet의 폭 변경을 실제 구현에서 찾을 수 있습니다.
9.1

논문의 질문

9.1 층을 더 쌓는데 왜 학습 오차가 커질까?

Kaiming He · Xiangyu Zhang · Shaoqing Ren · Jian Sun2015CVPR 2016

Deep Residual Learning for Image Recognition

논문은 깊은 plain network가 얕은 대응 모델보다 훈련 오차가 높아지는 현상을 보였습니다. 이것은 단순히 훈련 데이터를 외워서 테스트 성능만 나빠지는 과적합과 다릅니다. 연구진은 각 블록이 원하는 함수를 처음부터 만드는 대신 입력에서 얼마나 달라져야 하는지를 학습하도록 바꾸었습니다.

원 논문 보기 ↗

논문의 논리는 이렇습니다. 얕은 모델에 층을 추가해도, 추가 층이 아무 변화도 주지 않는 항등 함수라면 최소한 기존 결과를 유지할 수 있어야 합니다. 그런데 실제 최적화는 그런 해를 쉽게 찾지 못했습니다. residual learning은 그 항등 경로를 구조에 직접 넣습니다. 이는 기울기 소실만을 없애는 만능 해법이라는 뜻이 아니라, 깊은 망의 최적화를 쉽게 하려는 설계입니다.

9.2

실습 9.1 · 덧셈 따라가기

9.2 원래 입력에 변화량을 더한다

덧셈 전의 목표 변환을 H(x)라고 할 때 블록은 차이 F(x)=H(x)−x를 학습합니다. 입력과 출력의 크기가 같으면 identity shortcut은 x를 그대로 전달하고, 주 경로가 만든 F(x)와 원소별로 더합니다. 이 구현은 덧셈 뒤 ReLU를 적용합니다.

H(x) = F(x) + x→y = ReLU(H(x))

이 페이지의 숫자 실험은 특징맵의 한 원소만 떼어낸 모형입니다. 실제 블록에서는 텐서의 대응하는 모든 위치와 채널에 같은 방식으로 덧셈이 일어납니다. 슬라이더로 입력 x와 주 경로의 출력 F(x)를 바꿔 보세요.

입력 1.0
주 경로 · 학습한 변화량0.0
shortcut · 입력 그대로1.0
더하기 1.0→ ReLU
잔차 블록 출력1.0
같은 F(x)에 shortcut이 없다면0.0

F(x)=0이면 양수 입력은 그대로 전달됩니다.

항등 경로의 정확한 범위

이 구현은 덧셈 뒤에도 ReLU를 적용합니다. 따라서 F(x)=0이어도 음수 입력까지 항상 그대로 나오는 것은 아닙니다. 실습에서 x를 0 이상으로 제한한 이유입니다. 덧셈 뒤 활성화까지 항등으로 만드는 후속 설계는 pre-activation ResNet에서 살펴볼 수 있습니다.

9.3

블록의 두 경로

9.3 더하려면 모양이 먼저 같아야 한다

BasicBlock은 3×3 합성곱 두 번으로 F(x)를 계산합니다. ResNet18과 ResNet34가 사용합니다. Bottleneck은 1×1 → 3×3 → 1×1로 채널을 조절하며 ResNet50 이상의 모델이 사용합니다. 이 저장소의 Bottleneck 출력 채널은 내부 planes의 네 배입니다.

블록주 경로 F(x)사용 모델
BasicBlock3×3 → 3×3ResNet18·34
Bottleneck1×1 → 3×3 → 1×1ResNet50·101·152 및 확장 모델

같은 단계에서는 입력과 F(x)의 채널·높이·너비가 같아 x를 그대로 더할 수 있습니다. 새 단계의 첫 블록처럼 공간 크기를 절반으로 줄이거나 채널 수를 늘릴 때는 downsample 경로에 1×1 합성곱(필요하면 보폭 2)과 BatchNorm을 두어 모양을 맞춥니다. 이는 매 블록의 항등 shortcut과 달리 학습 파라미터가 있는 projection shortcut입니다.

크기 일치: F(x) + x→크기 변경: F(x) + Wsx

이 프로젝트는 차원이 달라질 때 항상 위 투영 경로를 사용합니다. 원 논문에서 비교한, 0으로 채워 채널을 맞추는 방식과는 구분해야 합니다.

논문에는 ImageNet용 ResNet 계열과 별도의 작은 CIFAR-10 실험 구조가 나옵니다. 이 저장소는 ImageNet형 stem과 4단계 구조를 유지한 채 분류 출력만 10개로 바꿉니다. 따라서 웹 실습의 크기 변화나 직접 학습한 결과를 논문의 CIFAR-10 수치와 일대일로 비교할 수 없습니다.

사전학습 가중치는 자동으로 내려받지 않습니다

backbone/ResNet.py의 pretrained 인자는 생성 함수에 있지만 가중치 로딩 부분은 주석 처리되어 있습니다. pretrained=True만으로 논문 또는 ImageNet 사전학습 가중치가 적용된다고 생각하면 안 됩니다.

9.6

실제 프로젝트 코드

9.6 덧셈 한 줄 전후를 읽기

아래는 backbone/ResNet.py의 BasicBlock.forward에서 빈 줄만 뺀 코드입니다. 오른쪽 해설을 선택하면 해당 줄이 강조됩니다.

backbone/ResNet.py · BasicBlock.forward
def forward(self, x):
    identity = x
    out = self.conv1(x)
    out = self.bn1(out)
    out = self.relu(out)
    out = self.conv2(out)
    out = self.bn2(out)
    if self.downsample is not None:
        identity = self.downsample(x)
    out += identity
    out = self.relu(out)
    return out

out += identity가 이 블록의 핵심입니다. _make_layer는 단계 첫 블록의 입력·출력 채널이나 보폭이 다를 때 conv1x1(..., stride)와 BatchNorm을 downsample에 넣습니다. 따라서 코드에서 투영 여부를 확인하려면 forward뿐 아니라 블록을 만드는 부분도 함께 읽어야 합니다.

ResNeXt는 그룹화된 변환의 수(cardinality)를 설계 축으로 제안합니다. 이 구현의 resnext50_32x4d는 groups=32, width_per_group=4를 사용합니다. wide_resnet50_2는 width_per_group=128로 ResNet50의 Bottleneck 내부 폭을 두 배로 합니다. 이름이 비슷하더라도 이것을 Wide Residual Networks 논문의 CIFAR용 특정 구조와 동일시하면 안 됩니다.
