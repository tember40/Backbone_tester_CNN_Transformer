제11장 · 연산을 나누고 좁은 곳을 연결하다MobileNetV2

합성곱을 무작정 줄이면 특징 표현도 줄어듭니다. MobileNetV2는 공간 필터링과 채널 혼합을 분리하고, 블록 안에서 잠시 채널을 넓혔다가 다시 좁힙니다. 마지막 좁은 층에는 비선형 활성화를 두지 않습니다. 어디에서 계산을 줄이고 어디에서 정보를 보존하는지 직접 따져 봅시다.

학습 목표

  • 일반 3×3 합성곱과 깊이별·점별 합성곱의 가중치 수를 비교할 수 있습니다.
  • inverted residual의 확장·공간 처리·선형 투영 순서를 추적할 수 있습니다.
  • 이 구현에서 shortcut이 사용되는 정확한 조건을 판단할 수 있습니다.
  • 32×32 입력과 width_mult에 따른 실제 출력 크기와 파라미터 수를 읽을 수 있습니다.
11.1

논문의 질문

11.1 작은 기기에서 무엇을 아낄까?

Mark Sandler · Andrew Howard · Menglong Zhu · Andrey Zhmoginov · Liang-Chieh ChenCVPR 2018

MobileNetV2: Inverted Residuals and Linear Bottlenecks

연구진은 좁은 입력·출력 사이에서 채널을 넓힌 뒤 깊이별 합성곱을 수행하는 inverted residual을 제안했습니다. 좁은 출력에 비선형 활성화를 적용하면 정보가 손실될 수 있다는 점에서, 투영 층을 선형으로 두는 설계도 핵심입니다. 논문은 정확도뿐 아니라 연산량과 파라미터 수의 절충을 비교합니다.

원 논문 보기 ↗

9장의 ResNet은 주 경로와 shortcut을 더해 깊은 모델의 학습을 돕습니다. MobileNetV2에도 더하기가 있지만, 좁은 표현에서 좁은 표현으로 연결한다는 점이 다릅니다. 블록 내부의 넓은 표현은 주로 변환을 계산하는 공간입니다. 두 모델을 같은 “skip connection”이라는 말만으로 묶지 말고 채널 흐름을 함께 보세요.

11.2

실습 11.1 · 가중치 세기

11.2 공간과 채널 연산을 분리한다

일반 합성곱은 출력 채널마다 모든 입력 채널의 3×3 값을 사용합니다. depthwise는 각 입력 채널에서 공간 필터를 하나씩 적용하고, 뒤의 1×1 pointwise가 채널을 섞습니다. 입력·출력 채널 수를 바꿔 가중치 수를 계산해 보세요.

일반: 9 × Cin × Cout↔분리: 9 × Cin + Cin × Cout
일반 3×39,2169 × 32 × 32
깊이별 3×3 + 점별 1×11,3129 × 32 + 32 × 32
가중치 수 비율7.02배일반 ÷ 분리

이 계산은 한 합성곱을 분리했을 때의 필터 가중치만 셉니다. 편향·BatchNorm·활성화와 블록의 확장·투영은 포함하지 않습니다. 따라서 위 비율을 전체 모델의 속도나 메모리 절감률로 읽으면 안 됩니다. 실제 실행 시간은 기기와 연산 구현에도 영향을 받습니다.

이 그림은 분리된 합성곱 한 번의 원리를 보여줍니다. 아래 11.3절의 MobileNetV2 블록에서는 입력에 1×1 확장을 먼저 적용하고, 확장된 채널에서 깊이별 3×3을 수행한 다음 1×1로 좁게 투영합니다.

11.3

실습 11.2 · 채널 흐름

11.3 좁게 들어가 넓게 계산한다

이 구현의 InvertedResidual은 입력 채널에 확장 비율 expand_ratio를 곱해 중간 채널 수를 구합니다. 비율이 1이면 첫 1×1 확장 층은 생략합니다. 마지막 1×1은 출력 채널 수로 다시 투영합니다.

입력24좁은 표현
1×1 확장144ReLU6
3×3 깊이별144ReLU6
1×1 투영24선형 + BN

보폭 1·입출력 채널 일치 → shortcut으로 입력을 더합니다.

이름이 “역잔차”인 까닭은 전통적인 bottleneck처럼 넓은 양끝을 좁힌 것이 아니라, 좁은 양끝 사이를 넓혀 계산하기 때문입니다. 이 저장소에서 더하기는 stride == 1이고 inp == oup일 때만 실행됩니다. 공간 크기가 바뀌는 보폭 2 블록은 shortcut을 쓰지 않습니다.

11.4

좁은 표현과 정보

11.4 마지막 층을 선형으로 두는 이유

확장 층과 깊이별 층에는 ReLU6가 붙지만, 마지막 1×1 투영에는 ReLU6가 없습니다. 차원을 줄인 뒤 또 값을 0 또는 6으로 잘라내면 이미 좁아진 표현의 정보를 더 잃을 수 있기 때문입니다. “선형”은 이 투영의 활성화를 생략한다는 뜻이지, 전체 블록이 선형 함수라는 뜻은 아닙니다.

투영 값 예시활성화 없음ReLU6 적용 시
−2−2 유지0으로 잘림
0.50.5 유지0.5 유지
77 유지6으로 잘림

이 표는 ReLU6의 잘림을 보여주는 작은 숫자 예시입니다. 실제 코드는 투영 합성곱 뒤에 BatchNorm을 적용하므로, 표의 값이 모델에서 그대로 관찰된다는 의미는 아닙니다.

11.6

실제 프로젝트 코드

11.6 그룹 수와 더하기 조건 찾기

아래는 backbone/MobileNet.py의 InvertedResidual에서 필요한 줄을 순서대로 뽑은 발췌입니다. 중간의 layers 구성은 실제 코드와 같으며, 강조할 해설을 선택해 연산의 역할을 확인하세요.

backbone/MobileNet.py · InvertedResidual
hidden_dim = int(round(inp * expand_ratio))
self.use_res_connect = self.stride == 1 and inp == oup
if expand_ratio != 1:
    layers.append(ConvBNReLU(inp, hidden_dim, kernel_size=1, norm_layer=norm_layer))
layers.extend([
    ConvBNReLU(hidden_dim, hidden_dim, stride=stride, groups=hidden_dim, norm_layer=norm_layer),
    nn.Conv2d(hidden_dim, oup, 1, 1, 0, bias=False),
    norm_layer(oup),
])

실제 forward는 조건이 참일 때 return x + self.conv(x), 거짓일 때 return self.conv(x)입니다. 합성곱과 정규화·ReLU6를 묶은 ConvBNReLU는 확장과 깊이별 단계에만 사용됩니다. 이 발췌의 마지막 두 줄은 묶음 바깥에 있으므로 선형 투영으로 남습니다.

이 구현은 3×3 시작 합성곱의 보폭 2와 단계별 보폭을 그대로 사용합니다. 그래서 32×32 입력은 시작부터 16×16이 되고 최종 특징맵은 1×1입니다. x.mean([2, 3])으로 공간 평균을 낸 뒤 Dropout(0.2)과 10-class 선형 분류기로 보냅니다. mobilenet_v2(pretrained=True)를 넘겨도 가중치 다운로드 부분이 주석 처리되어 있어 사전학습 가중치가 적용되지 않습니다.

효율을 판단할 때

가중치 수가 적다는 사실만으로 학습 속도나 실제 기기 지연 시간이 반드시 짧다고 결론내릴 수 없습니다. 정확도, 연산량, 메모리, 하드웨어 실행 시간을 같은 입력·설정에서 함께 측정해야 합니다.

11.8 좁은 연결과 넓은 계산

11장 핵심 정리

  • 깊이별 합성곱은 공간 패턴을 채널별로 처리하고, 점별 합성곱은 채널을 섞습니다.
  • 역잔차 블록은 좁은 입력을 확장하고, 깊이별 합성곱을 거쳐 좁은 출력으로 선형 투영합니다.
  • shortcut은 보폭 1이면서 입력·출력 채널 수가 같을 때만 사용합니다.
  • 32×32 CIFAR-10의 크기 흐름과 논문의 큰 이미지 결과를 직접 동일시하지 않습니다.
