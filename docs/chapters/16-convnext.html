제16장 · Transformer 시대에 CNN을 다시 설계하다ConvNeXt

ViT와 PVT를 본 뒤에는 “좋은 이미지 백본을 만들려면 반드시 Attention이 필요한가?”라는 질문을 던질 수 있습니다. ConvNeXt는 ResNet 계열 CNN의 구성과 학습 방식을 차례로 바꾸어 그 질문을 실험했습니다. 이 장에서는 무엇이 합성곱으로 남고, 무엇이 현대적으로 바뀌었는지 실제 구현과 함께 읽습니다.

학습 목표

  • ResNet식 stem·블록과 ConvNeXt의 설계 차이를 구분할 수 있습니다.
  • ConvNeXt-Tiny의 네 단계에서 격자·채널·블록 수를 계산할 수 있습니다.
  • 7×7 depthwise, 채널별 LayerNorm, 4배 확장 Linear, 잔차 연결의 순서를 설명할 수 있습니다.
  • 32×32에서 큰 커널이 실제로 읽는 특징 위치와 논문 규모의 결과를 구분할 수 있습니다.
16.1

논문 리뷰 · 비교의 출발점

16.1 CNN이 뒤처진 이유는 연산 자체일까?

Zhuang Liu et al.CVPR 2022

A ConvNet for the 2020s

저자들은 표준 ResNet에서 출발해 학습 절차와 설계 요소를 단계적으로 현대화했습니다. 결과인 ConvNeXt는 Self-Attention을 쓰지 않는 CNN입니다. 논문의 분류·검출·분할 비교는 “CNN 대 Transformer”라는 이름만으로 성능 차이를 설명하기 어렵다는 점을 보여줍니다. 다만 수치는 논문의 데이터·학습 조건에서 얻은 결과입니다.

원 논문 보기 ↗

여기서 “현대화”는 Transformer를 CNN 안에 넣는다는 뜻이 아닙니다. 패치처럼 입력을 나누는 stem, 공간과 채널 처리를 나누는 블록, LayerNorm과 GELU 같은 선택을 CNN 경로에 적용해 비교한 것입니다. 논문에서 사용한 긴 학습·증강·최적화 설정도 비교에 영향을 주므로, 아키텍처 변경 하나가 모든 성능 향상을 만들었다고 단정하면 안 됩니다.

16.2

ResNet에서 이어지는 흐름

16.2 익숙한 CNN 부품을 어떻게 바꿨나?

설계 축9장 ResNet의 출발점이 저장소의 ConvNeXt-Tiny
입력 축소7×7 stride 2 + MaxPool4×4 stride 4 합성곱 stem
주 블록의 공간 처리3×3 일반 합성곱7×7 depthwise 합성곱
채널 처리블록에 따라 3×3 또는 1×1 합성곱C → 4C → C Linear
정규화·활성화BatchNorm·ReLULayerNorm·GELU
층별 배치ResNet18: [2,2,2,2]ConvNeXt-Tiny: [3,3,9,3]

“더 큰 7×7 필터”가 곧바로 일반 7×7 합성곱을 뜻하지는 않습니다. depthwise convolution은 채널마다 별도의 공간 필터 하나를 적용하고, 다음 Linear 층이 같은 위치의 채널을 섞습니다. 11장의 MobileNetV2와 연결되는 부분이지만, ConvNeXt 블록은 MobileNetV2의 역잔차 블록과 배열 순서·정규화·활성화가 다릅니다.

16.3

ConvNeXt-Tiny의 공간 흐름

16.3 네 단계의 격자를 따라가자

저장소의 convnext_tiny는 단계별 채널 [96, 192, 384, 768], 블록 수 [3, 3, 9, 3]으로 구성됩니다. 입력 stem이 가로·세로를 4분의 1로 줄이고, 단계 사이의 2×2 stride 2 합성곱이 다시 절반씩 줄입니다. 각 단계의 블록 안에서는 공간 크기가 유지됩니다.

입력32×32×3
→
stem + 1단계8×8×96블록 3개
→
2단계4×4×192블록 3개
→
3단계2×2×384블록 9개
→
4단계1×1×768블록 3개

224×224 입력에서는 격자가 56→28→14→7입니다. PVT와 공간 단계 수는 비슷하지만, ConvNeXt는 각 격자에서 합성곱으로 공간 이웃을 처리하며 Attention의 Query·Key 표를 만들지 않습니다. 현재 코드의 최종 공개 출력도 네 특징맵이 아니라 전역 평균 → LayerNorm → 10개 분류 점수입니다.

한 블록을 분해하기

16.4 공간 처리와 채널 처리를 나눈다

입력H×W×C
→
공간7×7 DWConv
→
정규화LayerNorm
→
채널Linear C→4C
→
비선형GELU
→
채널Linear 4C→C
→
안정화Layer Scale
→
잔차+ 입력

Depthwise 7×7의 공간 가중치는 C채널에 대해 49C개입니다(편향 제외). C→4C→C 두 Linear의 가중치는 8C²개입니다. 예를 들어 첫 단계 C=96이면 각각 4,704개와 73,728개입니다. 따라서 “depthwise라서 블록 전체가 49C개의 가중치만 가진다”는 설명은 틀립니다. 이 숫자는 구조 이해용이며 실제 연산 시간·메모리 사용량과 같지 않습니다.

permute(0, 2, 3, 1)는 채널을 마지막으로 옮겨 같은 공간 위치의 C개 값에 LayerNorm과 Linear를 적용하기 위한 배열 변환입니다. 이것은 이미지를 ViT의 토큰 열로 바꾸어 Attention을 수행한다는 뜻이 아닙니다. 마지막에는 원래 (N,C,H,W)로 돌리고 ResNet처럼 입력과 더합니다.

16.5

실습 16.1 · 커널과 실제 입력의 겹침

16.5 7×7은 항상 49곳을 볼까?

단계와 커널 크기를 고르고 격자의 출력 위치를 눌러 보세요. 왼쪽은 그 위치를 계산할 때 참조하는 실제 특징칸, 오른쪽은 커널의 각 칸이 실제 입력을 읽는지 0 패딩을 만나는지 보여줍니다. 3×3은 차이를 보기 위한 비교 설정이며 현재 모델의 기본 커널은 7×7입니다.

공간 필터
특징 격자 · 출력 위치를 선택하세요

1단계 · 8×8 격자

채널 96 · 블록 3개

필터 창 · 회색은 패딩

7×7 depthwise 커널

선택 위치: 5행 5열

실제 입력 위치49
커널 공간 가중치/채널49
실제 위치와 겹친 비율100%

선택한 출력 위치에서 49개의 실제 입력 칸이 7×7 창에 들어옵니다.

이것은 블록 한 개, 채널 한 개의 한 출력 위치에 대한 도식입니다. 여러 블록을 거치며 누적 수용영역은 커지지만, CIFAR-10의 4단계 1×1 격자에서는 해당 블록의 depthwise 커널 중심만 실제 특징값과 겹칩니다. “7×7을 썼으니 마지막 단계에서 49개 서로 다른 위치를 읽는다”는 해석은 맞지 않습니다.

16.6

정규화와 잔차의 크기

16.6 LayerNorm, Layer Scale, DropPath는 같은 기능일까?

LayerNorm
블록 안에서는 채널을 마지막으로 둔 위치별 벡터를 정규화합니다. stem과 단계 사이에서는 channels_first 분기를 사용합니다. BatchNorm처럼 배치 통계를 학습 중에 누적하는 구조는 아닙니다.
Layer Scale
gamma는 C개 채널마다 하나씩 있는 학습 변수입니다. 기본 초기값 10⁻⁶을 블록의 변환 결과에 곱한 뒤 입력과 더합니다. 0으로 고정하는 것이 아니라 학습 중 변합니다.
DropPath
학습 중 일부 샘플의 잔차 가지 전체를 확률적으로 건너뜁니다. 추론에서는 작동하지 않습니다. 이 저장소의 기본 convnext_tiny는 drop_path_rate=0이라 실제로는 Identity입니다.

세 요소는 각각 값의 정규화, 잔차 가지의 초기 크기, 학습 중 가지의 확률적 생략을 담당합니다. 역할을 섞어서 “LayerNorm이 드롭아웃을 한다”거나 “Layer Scale이 공간 크기를 줄인다”고 이해하지 않도록 주의하세요.

16.7

실제 프로젝트 코드

16.7 각 설명은 어느 코드에 대응할까?

backbone/ConvNeXt.py의 여러 위치를 한 흐름으로 발췌했습니다. 오른쪽 항목을 누르면 해당 줄이 강조됩니다.

backbone/ConvNeXt.py · 핵심 경로
self.dwconv = nn.Conv2d(dim, dim, kernel_size=7, padding=3, groups=dim)
self.norm = LayerNorm(dim, eps=1e-6)
self.pwconv1 = nn.Linear(dim, 4 * dim)
self.act = nn.GELU()
self.pwconv2 = nn.Linear(4 * dim, dim)
self.gamma = nn.Parameter(layer_scale_init_value * torch.ones((dim)),
x = x.permute(0, 2, 3, 1)
x = input + self.drop_path(x)
nn.Conv2d(in_chans, dims[0], kernel_size=4, stride=4),
nn.Conv2d(dims[i], dims[i+1], kernel_size=2, stride=2),
return self.norm(x.mean([-2, -1]))
model = ConvNeXt(depths=[3, 3, 9, 3], dims=[96, 192, 384, 768], num_classes=num_classes, **kwargs)

발췌는 블록 초기화·forward·네트워크 초기화·생성 함수의 줄을 모은 것으로 단독 실행 코드는 아닙니다. gamma 정의는 조건부 표현식의 첫 줄만 보였으므로 전체 조건은 실제 코드에서 확인하세요. 특히 drop_path_rate를 별도로 주지 않으면 기본값은 0입니다.

16.8

논문 규모와 작은 이미지

16.8 같은 구조라도 32×32에서는 다르게 읽힌다

입력1단계2단계3단계4단계
논문 규모 224×22456×5628×2814×147×7
CIFAR-10 32×328×84×42×21×1

이 저장소는 기본 Tiny 구조를 작은 이미지에 그대로 적용하고, num_classes=10인 분류 헤드를 사용합니다. 따라서 블록 수·채널 수·7×7 depthwise는 같아도 마지막 단계의 공간 정보와 큰 커널이 실제로 읽는 위치가 달라집니다. 32×32 실험은 논문의 ImageNet 정확도를 재현하는 실험이 아니라 구조와 실행 경로를 익히는 실습입니다.

현재 forward_features는 네 단계의 결과를 내부에서 지나가지만 F1~F4를 외부로 반환하지 않습니다. 검출·분할에서 다중 규모 특징을 활용하려면 별도의 출력 인터페이스와 헤드가 필요합니다. 15장 PVT와 “둘 다 4단계니까 같은 종류의 연산”이라고 묶지 말고, PVT의 Attention과 ConvNeXt의 합성곱을 분리해서 비교하세요.

16.9

직접 실행 후 비교하기

16.9 결과를 해석할 때 무엇을 맞춰야 할까?

cifar10-lab train --model convnext_tiny --quick은 데이터 다운로드와 짧은 1 epoch 학습·검증을 실행합니다. 첫 실행은 연결과 출력 형상을 확인하는 단계입니다. ConvNeXt-Tiny는 현재 10클래스 설정에서도 약 2,783만 개 매개변수를 가지므로, 작은 CPU 환경에서는 quick 실행도 시간이 걸릴 수 있습니다.

ResNet18·PVT-Tiny·ConvNeXt-Tiny를 비교한다면 동일한 데이터 분할, 입력 크기, epoch, 증강, 최적화 조건과 시드를 기록하세요. 모델별 매개변수 수·학습 시간·메모리 사용량도 함께 보세요. 짧은 CIFAR-10 실행 결과만으로 논문의 ImageNet·검출·분할 우열을 일반화하지 마세요.

정리와 연습문제

16.10 현대 CNN의 핵심을 다시 말해 보기

16장 핵심 정리

  • ConvNeXt는 Attention 없이 ResNet 계열 CNN을 현대적인 구조와 학습 조건으로 다시 검토한 모델입니다.
  • 4×4 stem과 세 번의 2×2 다운샘플링으로 네 단계 공간 격자를 만듭니다.

  • 32×32의 마지막 1×1 단계에서는 7×7 필터의 49곳 중 중심만 실제 특징 위치와 겹칩니다.
